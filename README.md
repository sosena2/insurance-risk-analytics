# Insurance Risk Analytics

This repository contains a DVC-tracked insurance analytics workflow with a cleaning stage, EDA notebook, and reproducible pipeline outputs.

## Project Layout

- `data/MachineLearningRating_v3.txt.dvc` tracks the raw insurance dataset through DVC.
- `src/data_loader.py` handles dataset loading, separator detection, and validation.
- `src/clean_data.py` prepares the cleaned dataset for analysis.
- `notebooks/01_eda.ipynb` contains descriptive statistics, missing-value analysis, visualizations, and loss-ratio exploration.
- `.github/workflows/ci.yml` runs repository checks in CI.

## Setup

1. Create and activate a virtual environment.
2. Install dependencies:

	```bash
	pip install -r requirements.txt
	```

## DVC Workflow

Pull the tracked dataset and reproduce the pipeline end to end:

```bash
git clone <your-repo-url>
cd insurance-risk-analytics
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 2. DVC Data Setup
The raw source file is not stored in Git. It is versioned in [data/MachineLearningRating_v3.txt.dvc](data/MachineLearningRating_v3.txt.dvc), and the cleaned output is versioned separately in [data/cleaned_insurance_data.txt.dvc](data/cleaned_insurance_data.txt.dvc).

Pull the tracked dataset with DVC before running the pipeline or notebook:

```bash
dvc pull
```

To reproduce the cleaned dataset and DVC outputs from the tracked raw version, run:

```bash
dvc repro
```

This executes the pipeline defined in [dvc.yaml](dvc.yaml), reading `data/MachineLearningRating_v3.txt` and writing the cleaned version to `data/cleaned_insurance_data.txt`.
The pipeline documents the transformation lineage from raw input to cleaned output, while the separate `.dvc` files preserve version history for each dataset stage.

### 3. Verify the Pipeline End to End
After `dvc pull` and `dvc repro`, confirm the repo state with:

```bash
dvc status
```

The expected flow is:

1. Pull the raw dataset with DVC.
2. Run the cleaning pipeline with `dvc repro`.
3. Confirm the cleaned artifact is versioned in `data/cleaned_insurance_data.txt.dvc`.
4. Review the cleaned output in `data/cleaned_insurance_data.txt`.
5. Open `notebooks/01_eda.ipynb` for downstream analysis.

### 4. Notes on Tracked Data
- Raw data files remain under DVC control and are ignored by Git.
- Raw and cleaned datasets each have their own `.dvc` file, so lineage is explicit across stages.
- Cleaned outputs are generated by the DVC pipeline and should be reproduced rather than edited by hand.
- The repository includes a CI workflow under [.github/workflows/ci.yml](.github/workflows/ci.yml) for reproducibility checks.
